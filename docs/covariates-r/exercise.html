Exercise: Design matrices in R — limma

Goal

After this exercise you will be able to:

  • Predict the output of model.matrix (column names, entries, rank) before running it.
  • Set reference levels and level order with relevel and factor.
  • Check a design with qr(X)$rank and explain an NA coefficient from lm.
  • Run a limma analysis of bulk RNA-seq counts with design = ~ batch + sex + treatment, read log2 fold changes and adj.P.Val, and compare designs against a known truth.
  • Do the same for log2 intensities from mass-spectrometry metabolomics, with a continuous covariate (BMI).
  • Explain why a perfectly confounded design gives “coefficients not estimable”, and why only the experiment can fix it.

Background

A design formula is a recipe for the design matrix \(X\) in \(\mathbf{y} = X\boldsymbol\beta + \boldsymbol\varepsilon\) (see Design matrices for covariates). In R:

formula term columns of \(X\) coefficient means
intercept (always there) (Intercept), all 1s mean of the reference group
factor treatment (ctrl, treat) treatmenttreat treat minus ctrl
factor batch (A, B, C) batchB, batchC B minus A, C minus A
number bmi bmi change per BMI unit
  • The reference level is the alphabetically first level, unless you change it.
  • \(\boldsymbol\beta\) is unique only if qr(X)$rank equals ncol(X) (the columns are linearly independent). Otherwise there are infinitely many solutions (see Linear systems in R): lm and limma return NA for a column.
  • limma fits every row of a log2-scale omics table with the same \(X\). On the log2 scale each coefficient is a log2 fold change (logFC): 1 = doubled, \(-1\) = halved. adj.P.Val is the p-value adjusted for testing thousands of genes: among genes called at adj.P.Val < 0.05, about 5% are expected to be false.
  • If a covariate is unbalanced across the groups you compare, leaving it out of the design mixes its effect into the treatment effect (Confounding & Simpson’s paradox).

By hand

Do these on paper first. Then check each one in R (the code is in the solutions).

B1. Predict model.matrix. Six samples:

sample batch sex treatment
1 A F ctrl
2 A M treat
3 B F ctrl
4 B M treat
5 C F treat
6 C M ctrl

  1. Write the column names of model.matrix(~ batch + sex + treatment). How many columns are there?

  2. Write the full \(6 \times 5\) matrix.

  3. Samples 5 and 6 fail quality control and are removed. Write \(X\) for the four remaining samples. Which two columns are now identical? What are ncol(X) and qr(X)$rank? Which coefficient does lm report as NA?

B2. The order of levels. A time course has time stored as text: "0h", "6h", "24h", "48h".

  1. Which column names does model.matrix(~ time) give, and in which order?

  2. Write the line of R that puts the levels in time order. Which columns do you get then?

  3. If you instead code time as a number of hours, time_h, how many columns does \(X\) have? What does that model assume that the factor model does not?

B3. Confounded batches. Eight samples: samples 1–4 are controls sequenced in batch A, samples 5–8 are treated samples sequenced in batch B.

  1. Write \(X\) for ~ batch + treatment. What is its rank, and how many coefficients are there?

  2. What does lm return? What does limma’s lmFit say?

  3. Propose a new layout of the same eight samples over the two batches that gives a full-rank \(X\). Which layout is best, and why?

B4. limma coefficients and fold changes. A limma analysis uses design <- model.matrix(~ batch + sex + treatment) with batch (A, B, C), sex (F, M) and treatment (ctrl, treat).

  1. What does colnames(design) print? Which name do you give to topTable(fit, coef = ...) to get the treatment effect?

  2. A colleague writes topTable(fit, coef = 2). Which comparison does that report? Why is a name safer than a number?

  3. A gene has a mean log2 expression of 6.64 in the controls (about 100 on the original scale). Its logFC for treatmenttreat is 2. What is its expected value in the treated samples (same batch and sex), on the log2 scale and on the original scale? And if the logFC were \(-1\)?

B5. Reading lm output. For the drug/batch example from Confounding & Simpson’s paradox, R prints:

coef(lm(expr ~ treatment, data = g))
#    (Intercept) treatmenttreat
#           17.5           -3.0
coef(lm(expr ~ batch + treatment, data = g))
#    (Intercept)         batchB treatmenttreat
#             10             10              2

  1. From the second model, compute the predicted expression of a control in batch B and of a treated sample in batch A.

  2. In one sentence: why are the two treatmenttreat coefficients different, and which one is the drug effect?

B6. A continuous covariate in limma. A limma fit of one metabolite’s log2 intensity with design <- model.matrix(~ group + bmi) gives coefficients (Intercept) 10, groupdisease 1, bmi 0.1.

  1. Predict the log2 intensity for a healthy person with BMI 20 and for a disease patient with BMI 30.

  2. The two differ by 2 on the log2 scale, that is a factor 4. How much of that difference is due to disease and how much to BMI?

In R

Install limma once with BiocManager::install("limma") (see Install R).

R1 — Simulate a bulk RNA-seq experiment

We simulate counts so that we know the truth: 2000 genes, 12 samples in two sequencing batches, F and M samples, controls and treated. Genes 1–200 truly respond to treatment (LFC \(\pm 1.5\)), genes 101–600 differ between batches (LFC \(\pm 2\)), genes 1901–1950 are higher in M. The treatment is unbalanced across batches: batch A has 1 control and 5 treated samples, batch B the opposite.

library(limma)
set.seed(1)

# sample table: one row per sample
samples <- data.frame(
  batch     = factor(rep(c("A", "B"), each = 6)),
  sex       = factor(rep(c("F", "M"), times = 6)),
  treatment = factor(c("ctrl", rep("treat", 5), rep("ctrl", 5), "treat")))
rownames(samples) <- paste0("s", 1:12)

# true log2 fold changes, one row per gene
n <- 2000
lfc_treat <- rep(0, n); lfc_treat[1:200]   <- sample(c(-1.5, 1.5), 200, TRUE)
lfc_batch <- rep(0, n); lfc_batch[101:600] <- sample(c(-2, 2), 500, TRUE)
lfc_sex   <- rep(0, n); lfc_sex[1901:1950] <- 3
B <- cbind(lfc_batch, lfc_sex, lfc_treat)

# the same design matrix for every gene
X    <- model.matrix(~ batch + sex + treatment, data = samples)
base <- exp(rnorm(n, log(200), 1))              # baseline mean count of each gene
mu   <- base * 2^(B %*% t(X[, -1]))             # mean count: genes x samples
phi  <- 0.05 + 2 / base                         # negative-binomial dispersion
counts <- matrix(rnbinom(n * 12, mu = mu, size = 1 / phi), nrow = n,
                 dimnames = list(paste0("g", 1:n), rownames(samples)))
truth_de <- lfc_treat != 0                      # TRUE for the 200 DE genes

  1. Print table(samples$batch, samples$treatment) and X. Check that X is what you expect.

  2. Compute ncol(X) and qr(X)$rank. Can this design separate batch, sex and treatment?

  3. In the line that computes mu, what does B %*% t(X[, -1]) do? Why is it the same X for every gene?

R2 — One gene with lm

Gene g138 is one of the true DE genes (true LFC \(+1.5\)) and is also higher in batch B (true batch LFC \(+2\)). Fit it with lm on the log2 scale:

y <- log2(counts["g138", ] + 1)
coef(lm(y ~ treatment, data = samples))
coef(lm(y ~ batch + sex + treatment, data = samples))

Which model gets the treatment effect roughly right? Explain the other one with the table from R1(a).

R3 — limma with the full design

RNA-seq counts are first put on the log2 scale with voom, which also records how noisy each value is (low counts are noisier).

design <- model.matrix(~ batch + sex + treatment, data = samples)
v   <- voom(counts, design)
fit <- eBayes(lmFit(v, design))
tt  <- topTable(fit, coef = "treatmenttreat", number = Inf)
head(tt)

  1. Which coefficient names can you give to coef =? Did you predict them in B4?

  2. Look at tt["g138", ]. Compare its logFC with your lm estimate in R2 and with the truth.

  3. How many genes have adj.P.Val < 0.05? How many of them are truly DE, and how many are false positives? topTable sorts the genes, so put them back in order first: called <- tt[rownames(counts), "adj.P.Val"] < 0.05, then table(called, truly_DE = truth_de).

R4 — Leave batch out

Refit with design = ~ treatment (redo voom with the new design) and repeat R3(c).

  1. How many genes are called now, and how many of them are false positives?

  2. Most of the false positives come from one group of genes. Which group? Count them with lfc_batch != 0.

  3. Look at g138 again. What happened?

R5 — A perfectly confounded experiment

Now suppose the lab had put all controls in batch A and all treated samples in batch B:

samples_conf <- samples
samples_conf$treatment <- factor(ifelse(samples$batch == "A", "ctrl", "treat"))
table(samples_conf$batch, samples_conf$treatment)

design_conf <- model.matrix(~ batch + treatment, data = samples_conf)
fit_conf <- lmFit(voom(counts, design_conf), design_conf)
head(fit_conf$coefficients)

  1. Read the message. Confirm it with qr(design_conf)$rank.

  2. What does lm(log2(counts["g1", ] + 1) ~ batch + treatment, data = samples_conf) return for treatmenttreat?

  3. The message disappears if you use design = ~ treatment. Is that a fix? What would you tell the lab?

R6 — limma on metabolomics data

Mass spectrometry gives log2 intensities directly, so there is no voom step.

We simulate an untargeted mass-spectrometry metabolomics study: log2 intensities of 150 metabolites in 16 people, 8 healthy and 8 with a disease. Covariates: sex, BMI, and the MS run day (a batch). Metabolites 1–20 truly change with disease (log2 difference \(\pm 1\)); metabolites 21–45 rise with BMI (0.15 per BMI unit), 46–55 differ by sex, and every metabolite shifts a little between run days. The disease group has a higher BMI on average, and most patients were measured on day 2.

library(limma)
set.seed(2)
meta <- data.frame(
  group = factor(rep(c("healthy", "disease"), each = 8), levels = c("healthy", "disease")),
  sex   = factor(rep(c("F", "M"), times = 8)),
  day   = factor(c(1, 1, 1, 1, 1, 1, 2, 2,  1, 1, 2, 2, 2, 2, 2, 2)))
meta$bmi <- round(ifelse(meta$group == "disease", 29, 24) + rnorm(16, 0, 2.5))
rownames(meta) <- paste0("p", 1:16)

m <- 150
eff_group <- rep(0, m); eff_group[1:20] <- sample(c(-1, 1), 20, TRUE)  # disease
eff_bmi   <- rep(0, m); eff_bmi[21:45]  <- 0.15                         # per BMI unit
eff_sex   <- rep(0, m); eff_sex[46:55]  <- 1
eff_day   <- rnorm(m, 0, 0.7)                                           # run-day shift
X <- model.matrix(~ group + sex + bmi + day, data = meta)
B <- cbind(18 + rnorm(m, 0, 2), eff_group, eff_sex, eff_bmi, eff_day)
logint <- B %*% t(X) + matrix(rnorm(m * 16, 0, 0.4), m)   # metabolites x samples
dimnames(logint) <- list(paste0("met", 1:m), rownames(meta))
truth <- eff_group != 0                                   # the 20 changed metabolites

  1. Print table(meta$group, meta$day) and tapply(meta$bmi, meta$group, mean). Which covariates are unbalanced between healthy and disease?

  2. Fit the full model and list the top metabolites for disease:

design <- model.matrix(~ group + sex + bmi + day, data = meta)
fit <- eBayes(lmFit(logint, design))
tt  <- topTable(fit, coef = "groupdisease", number = Inf)
head(tt)

How many metabolites have adj.P.Val < 0.05, and how many of them are among the 20 true ones? Why is the coefficient called groupdisease?

  1. Repeat (b) with ~ group and with ~ group + sex + day (no BMI). A small helper:
count_hits <- function(f) {
  fit <- eBayes(lmFit(logint, model.matrix(f, data = meta)))
  tt  <- topTable(fit, coef = "groupdisease", number = Inf)
  called <- rownames(tt)[tt$adj.P.Val < 0.05]
  c(called = length(called), true = sum(called %in% rownames(logint)[truth]))
}
count_hits(~ group)
count_hits(~ group + sex + day)
count_hits(~ group + sex + bmi + day)

Which design gives false positives, and which metabolites are they? Why does adding day find more true metabolites, and why does adding bmi remove false ones but also lose some true ones?

Hints

Hint 1 — column names and the reference (B1, B2)

Each factor gives one column per level except the reference, which is the alphabetically first level (factor, relevel). The column name is the variable name followed by the level: batchB, sexM. Text is sorted character by character, so "24h" comes before "6h". See model.matrix.

Hint 2 — rank (B1c, B3, R5)

The rank is the number of linearly independent columns (qr). Two identical columns, or one column that is a sum of others, lower the rank by one. lm then reports NA for the later column (lm, “aliased coefficients”), and limma’s lmFit does the same with the message “Coefficients not estimable”.

Hint 3 — limma coefficient names (B4, R3)

In limma, coef = takes a column of the design matrix, by name ("treatmenttreat") or by position. The position depends on the order of the formula, so the name is safer. See topTable.

Hint 4 — log2 fold changes (B4c)

On the log2 scale you add the logFC. Back on the original scale that multiplies by \(2^{\text{logFC}}\): logFC 1 doubles, 2 quadruples, \(-1\) halves.

Hint 5 — counting calls against the truth (R3, R4)

A true positive is called and truth_de; a false positive is called and not truth_de. table with two arguments cross-tabulates.

Hint 6 — the simulation line (R1c)

B is genes \(\times\) 3 (one row of true coefficients per gene) and t(X[, -1]) is 3 \(\times\) samples (the columns of \(X\) without the intercept, transposed). Their product is genes \(\times\) samples: entry \((g, s)\) is \(\mathbf{x}_s \cdot \boldsymbol\beta_g\), the linear predictor of gene \(g\) in sample \(s\) (%*%).

Hint 7 — limma (R3, R6)

lmFit fits one linear model per row, eBayes shares variance information across rows, and topTable lists results for one column of the design, given by its column name in coef =. See the limma User’s Guide, chapter “Linear models overview”.

Solutions

Solutions — by hand

B1. (a) (Intercept), batchB, batchC, sexM, treatmenttreat: 5 columns (references A, F, ctrl).

  (Intercept) batchB batchC sexM treatmenttreat
1           1      0      0    0              0
2           1      0      0    1              1
3           1      1      0    0              0
4           1      1      0    1              1
5           1      0      1    0              1
6           1      0      1    1              0

The rank is 5: samples 5 and 6 are the only ones where sex and treatment differ, and that is enough to separate them.

  1. Without samples 5 and 6, batch C is gone (no batchC column) and sexM = treatmenttreat = \((0, 1, 0, 1)\): every M is treated and every F is a control. ncol(X) = 4, qr(X)$rank = 3. lm returns NA for treatmenttreat, the later of the two identical columns. (If batch is a factor that still has the level C, R keeps an all-zero batchC column, which lowers the rank as well.)
b1 <- data.frame(batch = c("A", "A", "B", "B", "C", "C"),
                 sex   = c("F", "M", "F", "M", "F", "M"),
                 treatment = c("ctrl", "treat", "ctrl", "treat", "treat", "ctrl"))
X <- model.matrix(~ batch + sex + treatment, data = b1)
qr(X)$rank                                              # 5
X4 <- model.matrix(~ batch + sex + treatment, data = b1[1:4, ])
ncol(X4); qr(X4)$rank                                   # 4  3
coef(lm(c(5, 9, 7, 11) ~ batch + sex + treatment, data = b1[1:4, ]))
#  (Intercept)  batchB  sexM  treatmenttreat
#            5       2     4              NA

B2. (a) (Intercept), time24h, time48h, time6h: alphabetical, because "2" < "4" < "6". The reference 0h is first by luck.

  1. time <- factor(time, levels = c("0h", "6h", "24h", "48h")) gives time6h, time24h, time48h.

  2. Two columns, (Intercept) and time_h. The numeric model assumes the expression changes linearly with hours (the step from 24 h to 48 h must be 4 times the step from 0 h to 6 h); the factor model lets each time point have its own mean.

B3. (a)

  (Intercept) batchB treatmenttreat
1-4         1      0              0
5-8         1      1              1

batchB = treatmenttreat, so the rank is 2 for 3 coefficients: infinitely many solutions.

  1. lm gives NA for treatmenttreat; its batchB estimate is batch and treatment together. lmFit does the same and prints “Coefficients not estimable: treatmenttreat”.

  2. Any layout where both batches contain both conditions gives rank 3. The best is balanced: 2 controls and 2 treated in each batch. Then batch and treatment are not related at all, and the treatment effect is estimated as precisely as possible.

B4. (a) "(Intercept)", "batchB", "batchC", "sexM", "treatmenttreat". Use coef = "treatmenttreat".

  1. Column 2 is batchB, so coef = 2 reports batch B vs A, not the treatment. If someone reorders the formula, the position of every column changes, but the name treatmenttreat still points to the treatment.

  2. On the log2 scale: \(6.64 + 2 = 8.64\). On the original scale: \(100 \times 2^2 = 400\). With logFC \(-1\): \(6.64 - 1 = 5.64\), that is \(100 \times 2^{-1} = 50\).

B5. (a) Control in batch B: \(10 + 10 = 20\). Treated in batch A: \(10 + 2 = 12\). (These are the data values.)

  1. The treated samples are mostly in the low batch A and the controls mostly in the high batch B, so ~ treatment mixes the batch difference into the treatment column; the adjusted model compares within batches, and +2 is the drug effect.

B6. (a) Healthy, BMI 20: \(10 + 0.1 \cdot 20 = 12\). Disease, BMI 30: \(10 + 1 + 0.1 \cdot 30 = 14\).

  1. Disease contributes 1 and the 10 extra BMI units contribute \(0.1 \cdot 10 = 1\). Half of the log2 difference of 2 is BMI, not disease.
Solutions — limma (R1–R6)

All numbers below are from running the code above (R 4.5, limma 3.60).

R1. (a)

table(samples$batch, samples$treatment)
#     ctrl treat
#   A    1     5
#   B    5     1

X has the columns (Intercept), batchB, sexM, treatmenttreat: batchB is 0 for s1–s6 and 1 for s7–s12, sexM alternates 0, 1, and treatmenttreat is 1 for s2–s6 and s12.

  1. ncol(X) = 4 and qr(X)$rank = 4: full rank. Each batch has both conditions, so the design can separate batch and treatment, even though it is unbalanced.

  2. Row \(g\) of B holds gene \(g\)’s true coefficients (batch, sex, treatment), and column \(s\) of t(X[, -1]) holds sample \(s\)’s dummy values. The product is the linear predictor of every gene in every sample. The samples are the same for all genes, so the same \(X\) is used for every row; only the coefficients differ between genes.

R2.

coef(lm(y ~ treatment, data = samples))
#    (Intercept) treatmenttreat
#           7.98          -0.24
coef(lm(y ~ batch + sex + treatment, data = samples))
#    (Intercept)  batchB   sexM  treatmenttreat
#           6.20    2.29  -0.37            1.41

The adjusted model gives 1.41, close to the true 1.5 (and batchB 2.29, close to the true 2). Without batch, the gene looks slightly down (\(-0.24\)): 5 of the 6 treated samples are in batch A, where this gene is low, and 5 of the 6 controls are in batch B, where it is high. That is Simpson’s paradox.

R3. (a) The column names of design: "(Intercept)", "batchB", "sexM", "treatmenttreat".

tt["g138", ]
#      logFC AveExpr    t  P.Value adj.P.Val
# g138  1.34    8.12 4.15  6.6e-05    0.0010

logFC 1.34, close to the lm estimate 1.41 and the truth 1.5.

called <- tt[rownames(counts), "adj.P.Val"] < 0.05
table(called, truly_DE = truth_de)
#        truly_DE
# called  FALSE TRUE
#   FALSE  1789   23
#   TRUE     11  177

  • Without bmi, most false positives are the BMI metabolites (met21–45): the patients have a higher BMI, so a BMI effect looks like a disease effect. For example met33 has disease logFC 1.0 (adj.P.Val 0.005) without bmi, but 0.21 (adj.P.Val 0.85) with it.
  • Adding day removes the run-day shifts from the noise, so every test gets more power: more true metabolites (19), but also more BMI false positives (20).
  • Adding bmi removes the false positives. But BMI and disease are correlated, so the model has less information to tell them apart and some true metabolites are lost (12 of 20). The cure for that is again the design: recruit patients and controls with similar BMI and spread them over the run days.

Where this leads

  • Bulk RNA-seq with DESeq2 (next unit): the same designs on the raw counts, size factors, and why fold changes of small counts are noisy.
  • Penalized linear models (Why penalize?): when \(X\) has more columns than samples, the rank condition fails by shape, and a penalty is one way to still get a unique \(\boldsymbol\beta\).
  • Interactions (~ sex + treatment + sex:treatment) and contrasts between any two levels (limma’s makeContrasts) use the same design matrix. We do not cover them further here.
  • limma’s eBayes (and DESeq2’s dispersion estimate) share information between genes. That is the same idea as the shrinkage in Hierarchical models (week 4).
  • Error models (week 4): why raw counts need a Poisson or negative-binomial model, which is what DESeq2 uses.
